# 流星锤 · 实现方案

> 依据作者 2026-10-19 口述规格整理。**每条规格都标了它落在哪个类/哪个字段**，实现时逐条对照。

## 一、物品形态

**不注册 19 个独立物品**，而是：

```
rotation_craft:flail              ← 唯一的物品类 FlailItem
  组件 rotation_craft:flail_ball  ← 内嵌的球（ItemStack，NBT）
```

理由与组合球同构：`ComboBallItem` 就是用 `ModComponents.COMBO_SOURCES` 存来源。
一个物品类 + 组件，意味着**所有数值/词条/信息显示都直接读内嵌球**，
不需要为 19 种球各写一遍。

**例外只有创造栏展示**：`ModCreativeTabs.BALLS` 的 `displayItems` 里遍历
`ModItems` 的球注册表，为每种球 `output.accept(FlailItem.of(ball))` 一次 ⇒
视觉上"每种独立"，实际是同一个物品的不同组件。

`FlailItem.of(ItemStack ball)` 是唯一的构造入口，内部：
1. 校验 `BallAmmo.isBall(ball)` 且 `BallClusterTier.of(ball).isClustered() == false`（满耐久）
2. 新 `ItemStack(FLAIL)`，`set(FLAIL_BALL, ball.copyWithCount(1))`

### 命名

`FlailItem.getName(ItemStack)` 覆写：
- 内嵌球是普通球 → `item.rotation_craft.flail.format`，参数 = 球的名字 ⇒「铁球流星锤」
- 内嵌球是组合球 → `item.rotation_craft.flail.combo.format`，参数 = 组合球拼出的 `铁-铜-木-石`

### 信息显示

tooltip 直接**委托给内嵌球的 tooltip**（`BallTooltip`），末尾追加流星锤专属几行
（线长 30 格、回收速度、破碎掉线）。**不复述词条**，避免两处维护。

## 二、实体

```
FlailHeadEntity extends Projectile      ← 独立类，不继承 BallProjectile
```

**为什么不继承**（作者重点强调）：锤头不能被捡、不能被怪接、不能单独存在。
继承会把这些行为一起带过来。做法是**复制 BallProjectile 的伤害与词条判定逻辑**
（提成一个 `BallImpactLogic` 工具类，两边共用），而**生命周期、拾取、回收全部自己写**。

### 字段

| 字段 | 说明 |
|---|---|
| `owner` (UUID) | 掷出者 |
| `flailStack` (ItemStack) | 锤头对应的流星锤栈（含内嵌球），用于取数值/词条/耐久 |
| `state` | `SPIN` / `FLYING` / `RETURNING` |
| `lineLength` | 当前线长（格） |
| `traitsDisabled` (boolean) | 首次回收后置 true，所有词条失效 |
| `slotIndex` (int) | 掷出时占用的背包格，回收必回这一格 |

### 状态机

```
[手持蓄力] ──松开右键──> FLYING ──线 30 格或手动回收──> RETURNING ──到达──> [收回手中]
     ↑                                                                    │
     └──────────────────── 回到手持蓄力（贴图恢复）────────────────────────┘
```

**SPIN**（手持时）：锤头不是自由实体，位置由客户端/服务端每 tick 按公式算出：
```
角度 += 2π / 20          // 每 tick
圆心 = 玩家位置 + forward × 0        // 具体见下
锤头 = 圆心 + 右侧方向 × 1.5 × cos(角度) + 前后方向 × 1.5 × sin(角度)
高度 = 玩家脚下 + 1.75
```
命中 ⇒ 基础伤害，击退 = 原值 × **0.5**。

**FLYING**：松手瞬间给初速（复用球的初速公式：`profile.launchSpeed()` × 蓄力系数），
之后照球的物理走（重力、弹性反弹、热量累积）。命中击退 = 原值 × **2.0**。

**RETURNING**：`速度 = 60 / profile.weight()` 格每秒，**受重力影响**，
方向朝掷出者主手。到达 2 格内 ⇒ 收回。

### 耐久

| 时机 | 扣除 |
|---|---|
| 原有逻辑（伤害、碰撞、特定效果） | 照旧 |
| **线达 30 格上限** | **1 点** + 速度归零 + 给一个朝掷出者的小速度（≈0.3 格/tick） |
| **开始回收** | **1 点** |
| 耐久归零 | 破碎：在掷出者**脚下**掉 1 根线，物品消失 |

### 词条失效

`RETURNING` 状态**第一次**进入时，`traitsDisabled = true`。
此后除 `弹性`（`bounce`）与 `重量`（`weight`）仍生效、耐久正常扣除外，
**所有 `FLAG_*` 词条一律跳过**，且**不再造成伤害**。直到下次 `FLYING` 开始时清除。

判定点：`BallImpactLogic` 入口统一判 `if (traitsDisabled) skip damage & flags`，
只在两处读 `bounce` / `weight` 的地方放行。

## 三、渲染

### 物品图标

**规格**（作者草图 + 2026-10-19 追加：绳子要像原版的线那样弯曲）：

| 元素 | 规格 |
|---|---|
| 球体 | 原球 `item` 贴图**缩到 13×13**，**左上偏移 3px** 贴到 16×16 画布 ⇒ 占 `(0..12, 0..12)` |
| 绳子空区 | 右下角空出的 **L 形**：右列 `x=13..15` 与 下行 `y=13..15` |
| 绳子颜色 | **深灰 `#404040`** —— 与原版 `minecraft:string` 同色，**不是白色** |
| 绳子造型 | **必须弯曲**，不许直来直去 |

#### 绳子为什么用 `#404040` + 弯曲

已核验原版 `assets/minecraft/textures/item/string.png`（16×16，163 B）：它是一根
**深灰色、盘绕成 S 形、带交叉转折**的线，在 16×16 里折了三次以上。
**视觉上「显得长」靠的就是这些转折** —— 同样长度的直线在 3px 的 L 区里根本看不出是绳子。

#### 具体走线（L 形区里折两次，视觉长度吃满）

```
          x: 12 13 14 15
y=12           ●              ← 起点压在球的右下角上（故意与球重叠 1px，显得绳子从球里穿出）
y=13              ●
y=14              ●  ●
y=15                 ●  ●     ← 终点顶到画布右下角
```

坐标序列（1px 宽，无抗锯齿）：
`(12,12) → (13,13) → (13,14) → (14,14) → (15,15)`

每段至少折一次方向，**不能是单调直线**（`(12,12)→(15,15)` 那种就是被否决的写法）。

#### 生成方式（脚本批量）

1. 读 `textures/item/<球>.png`
2. 最近邻缩放到 **13×13**
3. 新建 16×16 全透明画布，把球贴到 `(0,0)`
4. 按上面坐标序列画 `#404040` 的 1px 折线
5. 输出 `textures/item/flail/<球>.png`

#### 组合流星锤：绳子**独立成层**

⚠️ 关键设计：**绳子不能参与象限切分**，否则拼合时绳子会被切成四段。

```
物品栏渲染 = composite(
    select(combo_slot_1..4) 拼四象限球体,   ← 与组合球同一套 combo_piece_* 机制
    flail_string                    ← 单独的「绳子层」，恒在最上
)
```

所以贴图要分成两套：
- `textures/item/flail/<球>.png` —— 单个流星锤的**成品图**（球 + 绳子，直接给 19 种独立图标用）
- `textures/item/flail/quarter_<源>_<象限>.png` —— **只含球体象限、不含绳子**（供组合球拼合）
- `textures/item/flail_string.png` —— **单独一张绳子**（16×16，只有那根折线）

组合流星锤的 `items/flail.json` 用 `composite`：四层 `select` 拼象限 + 一层恒定 `flail_string`，
结构与现有 `items/combo_ball.json` 完全一致，只多叠最后一层。

### 世界渲染

两个 `RenderLayer`：
1. **锤头**：直接用球的物品渲染（`ItemRenderer` 画内嵌球），不做自定义模型
2. **线**：`WorldRenderEvents.AFTER_ENTITIES` 里画 `RenderType.lines()`，
   白色 `0xFFFFFFFF`，从主手位置到锤头位置，**无碰撞体积**

线的端点：掷出者主手世界坐标（用 `player.getMainHandItem()` 位置 + 眼睛高度偏移）。

## 四、配方

`data/rotation_craft/recipe/flail_<球>.json`（19 个）+ 一个组合球版本。

**作者指定：球与线各一个，相邻对角摆放。** 2×2 的 shapeless 表达为对角：
```json
"type": "minecraft:crafting_shapeless",
"ingredients": [ {球}, {"item": "minecraft:string"} ],
"result": <flail 内嵌该球>
```
⚠️ **但 shapeless 不校验"对角摆放"**。若要严格按位置，需用 `crafting_shaped`：
```json
"pattern": ["B ", " S"],   // B=球在左上，S=线在右下
"key": { "B": {球}, "S": {"item":"minecraft:string"} }
```
作者说的是"相邻对角"，用 **shaped 的 2×2 对角**才能保证。**采用 shaped**。

**必须满耐久**：`crafting_shaped` 的 result 无法约束材料耐久，
所以在 `FlailRecipe`（自定义 `CustomRecipe`）里校验：
内嵌球的 `BallClusterTier.of(ball).isClustered()` 必须为 false。

## 五、附魔

`FlailItem` 的 `supportsEnchantment` / `getEnchantmentValue` 只放行：
`DURABILITY`（耐久）、`MENDING`（经验修补）、`SHARPNESS`（力量，直接加伤）、
`FEATHER_FALLING`？（轻盈——需确认现有轻盈附魔的注册 id）、
现有 `极速`、`空气动力球` 三件自定义附魔。

加伤实现：`BallImpactLogic` 算伤害时叠加
`SHARPNESS 等级 × 1.0`（作者的"直接做加伤"）。

## 六、限制与特殊规则

| 规则 | 实现点 |
|---|---|
| 不进收纳袋 | `BallPouchItem.clusterizeSegment` 与右键存入处，判断 `is(FLAIL)` 直接跳过 |
| 不能切（切石机） | `BallCuttingGate` 里 `is(FLAIL)` 直接拒绝 |
| 回收必回原格 | 掷出时记 `slotIndex`，回收时 `inventory.setItem(slotIndex, flail)`；该格被占则找最近的空格，全满则丢在脚下 |
| 禁止切换物品栏 | `FLYING`/`RETURNING` 期间 `LocalPlayerMixin` 拦 `setSelectedItem` 与 `setItemInHand` |
| 锤头不能被捡 | `FlailHeadEntity.canBeCollidedWith` 返回 false；`BallPickupHandler` 只认 `BallProjectile` |
| 锤头不能被怪接 | `BallMobAI.pickupChance` 里只处理 `BallProjectile`，天然不含锤头（因为是独立类） |
| 锤头不能单独存在 | `FlailHeadEntity.tick()` 开头：`owner` 为空/离线/死亡 ⇒ 立刻 `discard()` 并把 flail 还给背包 |

## 八、作者已确认的四项（2026-10-19，按这些定稿）

### 1. SPIN 的圆周平面 —— **紧贴碰撞箱右侧、平行于玩家矢状面**

矢状面（sagittal plane）= 由「前后轴 + 上下轴」张成的竖直面。
所以圆周**在这个竖直面内**，法线是玩家的**左右方向**。

```
圆心 = 玩家脚下 + 1.75 格高，XZ 上紧贴碰撞箱右侧（约 +0.35 格偏移）
平面 = 前后 × 上下（法线 = 右向量）
锤头 = 圆心 + 前向量 × 1.5 × cos(θ) + 上向量 × 1.5 × sin(θ)
θ += 2π / 20   每 tick
```

换算成代码时用 `player.getLookAngle()` 取前向、`前向 × UP` 取右向，
**不要用世界坐标轴** —— 否则玩家转身时圆不跟着转。

### 2. 回收时线超长 —— **施加一个略大于玩家远离速度的回追速度**

不拉断、不拽玩家。每次「达到最大长度」那一刻：

```java
// 玩家远离速度在「锤头→玩家」方向上的投影
double awaySpeed = playerVel.dot(dirToPlayer);
double push = -awaySpeed + 0.5;          // 略大于，保证能往回靠
head.setDeltaMovement(head.getDeltaMovement().add(dirToPlayer.scale(push)));
```

并**同时**扣 1 点耐久（这一点作者原本就定了「到极限扣耐久 + 速度归零」，
现在归零后再给这个回追速度）。

### 3. 组合球**也有耐久** —— 组合流星锤同样要校验满耐久

**我原先写错了。** 事实：

- `BallItem` 的耐久 = `ModComponents.TOUGHNESS_LEFT` 组件，上限取 `profile.toughness()`
- `ComboBallItem extends BallItem`（L34）⇒ **组合球天然继承整套耐久系统**
- `BallClusterTier.of(stack)` 对组合同样有效

所以配方校验统一写：
```java
BallClusterTier.of(ball).isClustered() == false   // 满耐久（PRISTINE）
```
**对普通球和组合球一视同仁**，不需要分支。

### 4. 附魔是**数据驱动**的，注册点在 `data/rotation_craft/enchantment/*.json`

`ModEnchantments` 只提供 `ResourceKey`，没有 `register("...")` 调用 —— 这是正常设计，
不是"没做"。流星锤要放行的六个：

| 附魔 | 来源 |
|---|---|
| 耐久 | 原版 `minecraft:unbreaking` |
| 经验修补 | 原版 `minecraft:mending` |
| 力量（直接加伤） | 原版 `minecraft:sharpness`，伤害 += 等级 × 1.0 |
| **轻盈** | `ModEnchantments.LIGHTNESS` = `rotation_craft:lightness` |
| **极速** | `ModEnchantments.SWIFTNESS` = `rotation_craft:swiftness` |
| **空气动力球** | `ModEnchantments.AERODYNAMIC_BALL` = `rotation_craft:aerodynamic_ball` |

后三个的数值换算**直接复用现有静态方法**（`ModEnchantments` 里已有
「把等级换算成实际效果」的那一组），不要另写一套。

## 十、【尖啸】的线长屏障（2026-11-18 定稿）

**作者原话**：「【尖啸】触发的时候在线长上限处先生成一个屏障，让锤头可以撞到屏障后正常回归，
屏障在接受一次撞击后立即消失」（1.2.0.135 落地）

### 为什么需要

【尖啸】的射线距离上限是 `SHRIEK_MAX_RANGE = 256` 格，而 `shriek()` 是
「把整条轨迹算完、球直接停到落点」。对**球本体**这是对的（它没有绳子）；
但对**锤头**问题很大：

- **撞到方块**时：`level.clip` 命中，落点就在墙面上（通常远小于 30 格）⇒ 锤头停在近处 ⇒ 回归正常
- **打空气**时：`clip` 返回 MISS，落点取 256 格外那个点 ⇒ `shriekLand` 把锤头**直接钉在那儿**
  ⇒ 线长判定被越过 ⇒ 全靠绳子从 256 格拽回 30 格球面 ⇒ 玩家感觉「回归非常慢、绳子抽搐」

### 实现（BallExtraTraits.shriek()）

局部量 `range`，只在「有绳长约束的实体」上收紧：

`java
double range = SHRIEK_MAX_RANGE;
if (ball instanceof com.mcmodworkspace.moreballs.entity.FlailHeadEntity ropeHead) {
    double rope = Math.max(1.0D, ropeHead.maxRopeLength());
    double used = owner != null
            ? owner.getEyePosition().distanceTo(from)
            : from.distanceTo(ball.position());
    range = Math.max(0.0D, Math.min(range, rope - used));   // 量剩余绳长，不是固定 30
}
`

两处判断都改用 `range`：

`java
Vec3 to = cursor.add(dir.scale(range));                                   // 每段射程
if (bounce >= maxBounces || cursor.distanceTo(from) >= range) break;      // 总射程用完
`

### 为什么这是「一次性屏障」

- 屏障的语义 = **锤头飞不出这个球面**，射线走到那儿就收尾，`shriekLand` 照常结算
- **只活这一趟**：`range` 是本次调用里的局部量，**算完即弃**，
  不需要往世界里生成实体，也就没有「撞完要清掉」的收尾问题
- 撞击照常：`shriekSegment` 的 `miss` 参数在方法体里**没被用到**
  （只决定调用方要不要继续走下一段），落点音效／音爆／范围伤害都照旧

### 边界与注意

- **球本体（回响球，无绳）完全不受影响** —— `instanceof` 不进，`range` 仍是 256
- **量的是剩余绳长**，不是固定 30：出手点本身就在主人前方几格，写死 30 会落到 35 格上，照样超线长
- **判定线长 vs 实际线长**（1.2.0.134）：`FlailHeadEntity.snapThreshold` 给带【尖啸】的锤头取 40，
  但 `maxRopeLength` / `ropeLimit` 仍是 30 —— 玩家看到的、锤头停的地方都没变
- **回归与撞地不同源**（2026-11-18 排查结论）：
  撞地走落定分支里的 `if (returnToOwner && homingToOwner())`；
  打空气的锤头悬在半空、`hasSupportBelow()` 恒 false ⇒ 不落定 ⇒ 不经过那四个调用点。
  1.2.0.136 曾加过一条入口让两条路径共用，已按作者要求**回退**（1.2.0.137）
