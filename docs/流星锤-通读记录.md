### ⚠️⚠️ 致命数值问题：「60 / 重量」在重量 0 时会除零

回收速度 = `60 / profile.weight()`。而 **`weight` 的下界是 0 —— 回响球就是 0**
（L604 `.withWeight(0)`）。

```java
// ❌ 回响球流星锤会算出 Infinity
double speed = 60.0 / profile.weight();

// ✅ 必须夹一个上限
double weight = Math.max(0.5, profile.weight());     // 0 ⇒ 按 0.5 算 = 120 格/秒 已经很快
double speed = Math.min(60.0 / weight, MAX_RECOVER_SPEED);
```

我第一版 `FlailItem` 里写的是 `Math.max(0.1D, weight)` ⇒ 算出 **600 格/秒**，
比末影珍珠还快十倍，明显不对。**改成 0.5 并加 `MAX_RECOVER_SPEED` 硬上限。**

### 其它结论

- **初速度与重量是绑死的**：流星锤不用自己算初速，`profile.launchSpeed()` 直接给，
  物理射速读 `physicalVelocity()`。
- **组合球能拿到完整 profile**：`profileFor()` 对组合球会解析组件重新算出 profile，
  所以 `FlailItem.profileOf()` 对组合流星锤同样有效，**不需要额外分支**。
- **「除弹性与重量外所有词条失效」的落点**：`bounce` 与 `weight` 是 `BallProfile` 的字段，
  其余词条分两类 —— 布尔/数值字段（`sense` / `magnetic` / `wisdom` / `thunderThreshold` …）
  和 `flags` 位掩码。失效实现建议：**在锤头实体上存一个 `traitsDisabled` 布尔，
  在读取 profile 之后立即返回一个「只保留 weight 与 bounce」的裁剪版**
  （用 `DEFAULT.withWeight(p.weight()).withToughness(p.toughness()).withBounce(p.bounce())` 重建），
  这样不用在每个词条判定点各加一个 if。

### 对流星锤的直接结论

1. **锤头不能直接用 `BallProjectile`**（作者要求独立实体），但必须**照搬 `hasTrait` 这张映射表**——

### ✅ 「击退」的真相（本轮查清）

**模组自己从不施加击退** —— 全文 grep `knockback|push|setDeltaMovement` 之后确认：
`onHitEntity` 里只有 `hurtServer`，击退是**原版 `LivingEntity.hurtServer` 内部**按
`DamageSource` 算出来的。L4250-4252 的注释说得最清楚：

> `playerAttack` 的来源实体就是主人自己，`dealDefaultKnockback` 算出来的方向是 (0,0)，
> 但 `knockback()` 会用随机方向补一个 0.4 的推力……这里改用专属伤害类型，
> 它在 `no_knockback` 标签里，整段击退会被原版跳过。

### 伤害类型现状

`BallDamageTypes`（89 行）只有一个自定义类型：`TRUE_PHYSICAL`（L68）+ 工厂
`truePhysical(level, direct, owner)`（L78）。

`damageFromOwner()`（L4182-4215）的优先级：

```
【穿甲】traitFired(TRAIT_PIERCE)  → BallDamageTypes.truePhysical(...)      ← 最优先
【电击】traitFired(TRAIT_SHOCK)   → damageSources().source(LIGHTNING_BOLT, owner)
否则                              → playerAttack(player) / mobAttack(living) / thrown(this, null)
```

数据包 `data/rotation_craft/damage_type/` 只有三个：`ball_return` / `molten_burn` / `true_physical`。

### 结论：「击退 0.5 倍 / 2 倍」的正确实现

**不能乘系数改原版击退**（它藏在 `hurtServer` 里）。必须：

1. **新建一个带 `no_knockback` 标签的伤害类型**（例：`rotation_craft:flail_hit`），
   在 `data/minecraft/tags/damage_type/no_knockback.json` 里追加（**必须 `"replace": false`**）
   ⇒ 让原版那段击退整段跳过
2. **自己施加击退**：
   ```java
   double strength = 0.4 * mult;          // 原版默认 0.4
   // 旋转状态 mult = 0.5 ⇒ 0.2；扔出状态 mult = 2.0 ⇒ 0.8
   target.knockback(strength, dx, dz);    // dx/dz 取「锤头 → 目标」的水平方向
   ```

⚠️ 这一步同时解决了另一个隐患：旋转中的锤头每 tick 都可能碰到同一个目标，
如果沿用原版击退，玩家会被连续推着走；用手动击退就能精确控制「每次只推一下、力度 0.2」。

### `impactDamage()` L753-774 —— 伤害公式（可直接照搬）

```java
double base = this.launchSpeed > 1.0E-4D ? this.launchSpeed : this.profile().physicalVelocity();
if (base <= 1.0E-4D) return this.damage;
double hitSpeed = this.getDeltaMovement().length();
float ratio = (float) (hitSpeed / base);
float result = this.damage * ratio;      // ★ 无上限
```

**基准是「实际出手速度」`launchSpeed`（在 `shoot()` 里记的），不是 `physicalVelocity()`**
—— 后者不含蓄力与附魔，拿它当除数会让蓄力被算两次。

**流星锤怎么用**：
- **旋转状态**：速度是圆周运动速度，不是飞行速度 ⇒ **不能套这个公式**，
  直接 `damage × 1.0`（作者的「依照基础伤害造成伤害」）
- **飞出状态**：照搬公式，但要保证 `launchSpeed` 在松手那一刻记下来

### ✅ 击退方案已被现有代码验证

L4249-4252 的原话：

> 这一下**不能**用 `damageFromOwner()`（那是打受害者用的 playerAttack / mobAttack）。
> playerAttack 的来源实体就是主人自己，dealDefaultKnockback 算出来的方向是 (0,0)，
> 但 knockback() 会用随机方向补一个 0.4 的推力、并把水平速度减半 —— 疾跑就是这么断的。
> **这里改用专属伤害类型，它在 no_knockback 标签里，整段击退会被原版跳过。**

⇒ 「用专属 no_knockback 伤害类型 + 手动施加击退」这条路**工程里已经在用**
（`ModEnchantments.returnDamage` + `AERODYNAMIC_SELF_DAMAGE`），
流星锤照这个模式新建 `flail_hit` 即可，不是我的臆测。

### ⚠️ 流星锤的回收**不能**用 `deliverReturned`

作者明确要求「被任意方式回收的锤头都将回到**原本那一格**」，
而 `deliverReturned` 的顺序是「袋子中转 → 背包最前 → 快捷栏最前 → 掉落」。
所以流星锤要自己写：**先试原格 → 原格被占就找最近空格 → 全满掉脚下**。

### `burst()` L4348-4415 —— 破碎（68 行，可对照但不照搬）

| 行 | 内容 | 流星锤 |

### ⚠️ 流星锤的破碎与【变形】冲突

作者指定：**「流星锤耐久耗尽破碎时，将在掷出者脚下掉落一根线」**。

而 `burst()` 的 L4369-4376 对【变形】的处理是「不变碎裂、原地变成方块」，
并且**直接 `return`**——如果流星锤照搬，就会出现「变形了但没有掉线」。

**结论：流星锤的破碎流程自己写，不吃【变形】。**
理由：流星锤的本体是**物品**（绳子 + 球），不是纯材质球；把它变成一块金块没有意义，
而作者明确指定了破碎产物是**线**。其余词条（【尖刺】等）照常触发，只有【变形】排除。

### `comboSourceFor(profile)` L4429-4440 —— 组合球的掉落来源

组合球不是把四个来源的掉落表全跑一遍，而是**等权重随机抽一个来源**、
只跑那个来源的表。抽签只做一次、结果复用（否则「先问掉落表、再问是不是钻石球」会抽两次）。

流星锤不用这个（掉落固定是线），但**组合流星锤的命名与图标**要复用它的思路：
`BallFragments.parseIndexes(COMBO_SOURCES)` + `BallFragments.sources()`。
